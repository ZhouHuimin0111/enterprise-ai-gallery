# 简历描述与面试准备

项目：**企业级 AI 图片管理系统（FrameHub）**

GitHub：https://github.com/ZhouHuimin0111/enterprise-ai-gallery

技术栈：Java 21、Spring Boot、MyBatis Plus、MySQL、Redis、COS、百炼 API、WebSocket、Hutool、Knife4j、Docker、Testcontainers。

## 简历精简版

基于 Spring Boot 与 MyBatis Plus 实现前后端分离的图片管理平台，支持公共审核图库、个人私有空间和团队共享空间。封装统一响应、错误码、全局异常处理与可信来源 CORS，通过 Redis 共享 Token 会话和四级团队角色实现图库隔离与权限校验。采用 MySQL 条件更新核算空间配额、版本 CAS 防止并发编辑覆盖，结合 WebSocket 与 Redis Pub/Sub 同步跨实例修改；使用 COS 私有桶适配器存储图片，支持 JSON 标签多维检索、批量管理及裁剪旋转。封装百炼异步绘图 API，持久化任务状态、幂等键和生成结果关联，支持任务轮询与进程重启恢复；接入 GitHub Actions 验证权限、并发一致性和桌面/手机操作流程。

## 可以展开的技术点

- 对象存储与数据库非原子事务：先写清理意图，失败上传与替换旧文件进入可重试清理队列。
- 重复收费风险：提交状态先持久化，超时/崩溃不确定结果标记 UNKNOWN，不盲目重复 POST。
- 图片与 AI 成功状态同事务关联，任务重复轮询不会重复落图；同用户请求幂等键校验请求参数。
- JSON 数组类型处理器、参数化 JSON_CONTAINS、分页上限、排序白名单、成员关联联合索引。
- 公开 Cache Aside + 30 秒 TTL，私有/团队查询每次先鉴权；全局管理员不天然拥有私有数据访问权。

## 已验证的可选补充

基于 Testcontainers 与 GitHub Actions 通过 30 项后端测试、8 项桌面/手机浏览器测试及双实例 HTTP/WebSocket 链路验证。并发正确性测试中，20 个上传请求在两张容量限制下仅接受 2 个，16 个同版本编辑请求仅 1 个成功；在 SUBMITTED 阶段重启两个应用后，原演示任务继续完成。SQL 核验配额偏差、重复成员及成功任务缺图均为 0。

以上可按简历篇幅选用，属于测试环境结果；详细证据见 [验证记录](VERIFICATION.md)，不应改写为生产 QPS 或线上性能收益。

## 面试问题

1. 什么数据在 MySQL，什么在 Redis，为什么会话 key 存 Token hash？
2. 同时上传 20 张图片时，空间容量是怎样避免被突破的？
3. 配额扣减后图片插入失败，事务如何回滚？对象写成功但 DB 失败如何补偿？
4. 成员 VIEWER、EDITOR、ADMIN、OWNER 的边界是什么？邀请如何避免同时接受两次？
5. 公共图片编辑后为何重新审核？为什么私有桶不能直接改成公共读？
6. 两人保存同一图片时如何处理旧 version？怎么保留用户未提交草稿？
7. Redis Pub/Sub 断连会丢消息吗？为什么最终状态应从 MySQL 获取？
8. AI POST 超时是否代表云端未收到？为什么不用“失败就重试”？
9. 已知 task ID 重启后怎样恢复？保存生成图片与成功状态之间如何避免重复？
10. 演示 provider 的结果与真实 AI 有什么区别？真实 COS/百炼还需要哪些账号与联调步骤？

默认演示模式不调用模型。只有自行配置真实云凭据并完成联调，才可在面试中称“已完成云端实测”；当前可说“实现 COS/百炼适配器并做契约测试”。不要虚构生产企业经历、模型效果、QPS 或性能提升百分比。
